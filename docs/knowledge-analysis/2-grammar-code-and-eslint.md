## 2. The model

```
                 contexts/ui  (universal meaning, rule ids X-n, 178 ids)            contexts/hfs/rules.yaml (R-n laws,
                     |  generate-rule-catalog.mjs                                     enforcers[], failure codes)
                     v                                                                     ^   (lists enforcer ids by hand)
  @starci/grammar  src/common  -- COMMON_UI_RULE_IDS, data-contract stamps,               |
  (Common contract: renderers, props, anatomy, states, scales)                            |
        |  defineGrammarFamily(id, styles, replacements, extensions)                      |
        +-- core (StarCi)  dna.ts + styles.css      --+                                   |
        +-- offset-pop     dna.ts + 4 css           --+-- grammar-knowledge.mjs census --> contexts/grammars/<fam>/DNA.yaml
        +-- heritage       dna.ts + styles.css      --+   (tracked, measured blocks + authored prose, drift-checked)
                                                                                           |
  app code  --imports-->  @starci/grammar/<family>      contexts/grammars/<fam>/{family,idioms,playbook}.yaml (authored)
     ^
     |  linted by
  @starci/eslint-canon-fe (universal; but also button-intent, control-height, R318 surface rules)
  @starci/eslint-grammar-starci (named for one family, actually holds the Common-contract rules)
     ^  re-exported by
  @starci/eslint-grammar-offset-pop (no own rules)        heritage: no lint package at all
```

The governing boundary rule is FE-RULE-OWNERSHIP (`contexts/code/fe/index.yaml:29-52`), four ordered questions:
1. holds for any design system -> universal knowledge (`contexts/ui`, `contexts/hfs`);
2. one family's visual value -> that Grammar's DNA and `styles.css`;
3. how to call one Grammar's components (names, props, variants, sizes) -> that Grammar's lint package;
4. checkable regardless of Grammar -> universal canon-fe, which "names no family-specific component, prop, variant or size".

So in principle: **knowledge** selects and explains meaning; **the grammar package** owns values and API, and proves coverage of the
knowledge rule ids through conformance + `data-contract` stamps; **the grammar eslint package** owns executable checks on app code that
calls that API, and cites the knowledge fact it enforces. In practice the binding is spread over four places (rule meta, `rules.yaml`
enforcers, the lint docs' "Catalogue:" line, the sync list) and the three layers leak into each other (section 4).

## 3. The thinking the legacy encodes

**Common vs family.** "Common owns the typed props, semantics, renderer anatomy, universal states and scales … A family changes
presentation only: props, DOM, ARIA and keyboard behaviour stay the same" (`packages/grammar/README.md:3-10`). A family is
`defineGrammarFamily` with replacements typed `ComponentProps<Common[Name]>` and extensions that may not collide
(`src/common/registry.tsx:19-23`): the type system forbids a family from changing a Common prop.

**Intent, not variant (Button/IconButton).** Apps declare what a command *does*: `commit | alternative | dismiss | neutral | destructive`,
and `step: entry|confirm` only for destructive (`src/core/buttonIntent.tsx:9-16`). The variant is derived from intent x *placement*
(`decision | item | chrome`, plus `navbar` for icon buttons) supplied by the surrounding Grammar composition, never by the button
(`buttonIntent.tsx:39-41` "Placement belongs to the Grammar composition, never to a Button's appearance props"). The mapping
(`src/core/dna.ts:36-45`): commit is primary in a decision area and in chrome but secondary inside a repeated item (one primary per view;
a list of primaries is noise); neutral is outline in a decision area, ghost in items/chrome, tertiary in the navbar; destructive is
`danger-soft` at entry and solid `danger` only at the confirm step (inside the AlertDialog). That is why the variant list is the vendor's
seven (`Button/index.tsx:8-12`, "HeroUI v3 buttonVariants one to one") and why apps get no `variant`.

**Sizes.** `ButtonSize = sm | md | lg | control` (`Button/index.tsx:13`). The owner ruling `control-height-40` makes 40px the one default;
`sm` only when every control in the row is nested/dense; `lg` only for a landing hero; `control` is the bar-control height shared by
every navbar control (`packages/eslint/fe/docs/control-height.md`, `starci/playbook.yaml:189`).

**Accent fill vs accent text.** "`accent` is the brand FILL … where the accent is painted as TEXT … the family reads `accentText`, which is
themed because the violet fill is too dark to read on the dark canvas (3.95:1)" (`src/core/dna.ts:8-14`); Offset Pop repeats the
reasoning with its own WCAG table and puts ink, not white, on pink because white is 3.40:1 (`src/offset-pop/dna.ts:1-40`).

**Status: solid vs soft pair.** "A STATUS TONE HAS TWO FACES. The SOLID tone is a fill … A status shown as TEXT or as an ICON uses the SOFT
pair, the way a HeroUI flat Chip does" (`status-colors.mjs:6-10`); knowledge: `tone.yaml:118-122`, `contrast.yaml:65-67` (owner decision
2026-09-30 lowering the soft pair to 3:1).

**Elevation by depth.** Top surface = shadow without border, nested = border without shadow (`src/core/dna.ts:117-120`); Offset Pop's
deliberate departure keeps both at top depth as its signature (`offset-pop/conformance.ts` BOUNDARY-6).

**Scale is whole rungs.** "The rungs are whole and unevenly spaced, so half of one is not 'between two rungs' - it is off the ladder"
(`tokens.mjs:12-13`); knowledge: rule id = ordinal on the closed `COMMON_SPACING_SCALE`, diverging from Tailwind numbers from GAP-5 on
(`gap.yaml:58-59`).

**Heading = one decision of tag and size.** "the tag a screen reader builds the document outline from, and the size a reader sees. Set
separately they drift" (`typography.mjs:45`); levels stop at 4 because "a fifth means the page
has nested further than a reader can hold". `Heading` maps level 1..4 to FONT-4..FONT-1 (`Heading/index.tsx:25`).

**Glyphs: ask for a meaning, not a library.** "Reaching for it here decides three things at the call site - which library, which glyph, how
big" (`icon.mjs:98`); two cuts only, 24/outline and 16/solid (`icon.mjs:51`); and a design lesson for rule authors: "a rule that names one
vendor protects one vendor, and a rule that scans one family of utilities protects that family" (`icon.mjs:11-13`).

**Raw tags.** A tag is refused only when the Grammar has a component that renders it; `div`, `aside`, `article` stay legal "there is
nothing to compose instead, and refusing it would demand a workaround" (`grammar-boundary.mjs:10-13`).

**Static proof refuses to guess.** Unknown spreads, calls and unresolved values neither prove nor refute (`app-shell.mjs:24-31`,
`menu-entries.mjs` "Anything it cannot see through … it leaves alone"). Navbar rules follow local constants, aliases and namespace imports.

**Conformance as accounting.** Every family must classify every contexts/ui rule id as inherited or family-owned with evidence that
"names the mechanism" (`offset-pop/conformance.ts:3-22`); the catalogue is generated because "a conformance check against a wrong catalog
keeps passing" (`common/conformance.ts:4-8`).

### 4.2 Contradictions

1. **Fractional rungs.** `no-fractional-step` says "there is no case where the right answer is half of one" (`tokens.mjs:32`), yet both
   family scales publish `0.5`, `1.5`, `2.5` (`core/dna.ts:131-135`, `offset-pop/dna.ts:162-166`) and add `5/10/12/16` that the "closed"
   Common scale (`spacing.ts`) lacks. Knowledge says the scale is closed (`gap.yaml:58`). Three answers to "what is the scale".
2. **Two heading rules disagree on the owner.** `typography.mjs:17-19` exempts an app leaf named `Heading` in `fe.components`;
   `no-raw-structural-element` refuses `h1-h6` in the same slot. Any `<h2>` in app code is reported twice, and the exemption is dead (no
   scaffold ships `leaves/Heading`).
3. **Control size.** `navbar-control-size` demands `size="control"`; canon-fe `control-height` says omit `size` (or `md`/`control`, "the
   same 40px"). Two packages, two instructions for one fact.
4. **README contradicts the lint.** Offset Pop example `<Button variant="primary">Play</Button>` (`README.md:155`) is refused by canon-fe
   `button-no-variant` / `button-intent-required`. The app-shell example imports `@heroicons/react/24/outline` in an app component
   (`README.md:79`), which `no-vendor-icon-outside-icon-leaf` refuses outside the app `Icon` leaf, while Grammar's own API takes glyph
   components (`source`, `iconSource`).
5. **Silent default family.** `ButtonIntentFamilyProvider` falls back to `STARCI_CORE_DNA.intent` for any unknown family

## 5. Proposal for the new harness

### 5.1 Principle: three layers, one owner each, generated joins

| Layer | Owns | Never contains |
| --- | --- | --- |
| `contexts/ui/**` | universal meaning and the rule ids (`GAP-n`, `FONT-n`, `FE-APP-SHELL-n`, …), with the reasoning | Grammar component, prop, token or class names; values; enforcer lists |
| `contexts/grammars/<family>/` | the family's design reasoning: why its DNA chooses what it chooses, idioms, product-agnostic playbook | values (they are in `dna.ts`/CSS), lint recipes, product page types |
| `packages/grammar` | values (DNA, scales, tokens), Common API, renderers, conformance evidence, `data-contract` stamps | prose rules |
| `packages/eslint/grammar-*` | executable checks on app code calling the Grammar API; each rule's `meta.docs.knowledge` is THE binding to a fact | a second copy of values: they import generated vocabulary from the grammar |

### 5.2 Keep

FE-RULE-OWNERSHIP (restated to match the packages, see 5.4); the intent/placement model; `defineGrammarFamily` typing; `data-contract`
stamps + `defineGrammarRuleConformance`; generated `rule-catalog.generated.ts` and `status-tones.generated.mjs` (the right pattern);
the spec that verifies `GRAMMAR_OWNERS` against grammar exports and the spec that every citation resolves; "refuse to guess" static proof;
all reasoning quoted in section 3, moved into knowledge where it is design thinking (accent fill/text, solid/soft, depth elevation, whole rungs, heading tag+size, glyph meaning).

### 5.3 Merge, drop, move into code

1. **One family registry in code** (`packages/grammar/src/families.ts`): id, entry, stylesheet, DNA module, lint package+factory. Generate
   `grammars/index.yaml` `families`, `GRAMMAR_FAMILIES`, the fe-stack/canon-pins family rows and the lint allow-list from it; replace the
   `buttonIntent.tsx:34` ternary with a lookup that throws on an unknown family. One id per family (`core` vs `starci` vs `starci-core` -> pick one).
2. **Intent map, arrangement, iconSize -> Common** (they are identical in three DNAs); a family overrides only if it differs.
3. **One spacing scale.** Decide whether fractional rungs exist; make `COMMON_SPACING_SCALE` the only scale, generate the lint regex
   and the `gap.yaml` value column from it; remove family `*_SPACING_SCALE` copies.
4. **Generate lint vocabulary from the grammar** (like status tones): `HeadingLevel` depth, glyph steps/cuts, `BAR_CONTROLS`/`BAR_WRAPPERS`/`OVERLAYS`
   (from a `role` tag in the registry), `GRAMMAR_OWNERS`.
5. **Rename/split the lint packages:** `eslint-grammar-common` (rules on the Common API, inherited by every family), and a per-family
   package only when a family adds API (Heritage `Brand`). Every catalogued family gets a factory, even if it only re-exports Common; a
   family without one fails closed. Drop the dead `grammar-offset-pop/runtime/`.
6. **Move universal checks out of the grammar lint to canon-fe:** `no-unresolved-token-class`, `vendor-primitive-has-named-owner`,
   `no-vendor-icon-outside-icon-leaf`, `no-inline-svg-outside-brand-mark-leaf`, `slot-status-through-slotview`. Move Grammar-API checks
   out of canon-fe into the Common grammar lint: `button-intent`, `control-height` (then merge it with `navbar-control-size`).
7. **Merge the heading rules** into one (`no-raw-structural-element` already covers tags; keep the depth message) and drop the dead `leaves/Heading` exemption.
8. **Drop** `no-decorative-icon-in-metric-cell` (product component); move destructive and create term lists into one i18n phrase catalogue
   owned by the lint package (not `modules/goal`), English-first per the runtime language ruling.
9. **Binding has one owner: the rule's `meta.docs.knowledge`.** Generate `rules.yaml` `enforcers[]` (or the reverse index an agent reads)
   and the sync file list from rule metadata; fix the three wrong citations; put `code`/`fix` from `why.mjs` into `meta` and delete `why.mjs`.
10. **Docs are generated** per law from rule meta + cited knowledge text + spec valid/invalid cases; delete the hand-written `docs/*.md`
    and the README App-shell restatement (README links to the generated catalogue and the knowledge ids).
11. **DNA.yaml leaves knowledge.** The measured part becomes a generated, untracked artefact (or is read straight from `dna.ts` by the
    agent tool); the authored part (gaps, observations) moves into `family.yaml`. Authored prose stops carrying counts.
12. **Scrub universal knowledge** of family API names (R313 law, app-shell case-3, gap.yaml token/class columns); the family playbook
    keeps the concrete recipe. Strip release-history ids (`alpha-31`, `0.5.0`) and stale ids (`ICON-n`, `TYPESET-n`, `DRAWING-4`,
    `CONTROL-HEIGHT-1` -> declare it or drop it).
13. **Fill gaps** with rules where static proof is possible: off-scale whole steps, one icon size per region (per JSX region), one page heading.

### 5.4 Target layout (this area)

```
contexts/
  ui/                         # universal meaning (shared with area 3); no Grammar API names
  grammars/
    index.yaml                # GENERATED from packages/grammar/src/families.ts (agent reads: which families exist)
    <family>/
      family.yaml             # authored: identity, design reasoning per DNA group, gaps (agent at authoring)
      idioms.yaml             # authored, product-agnostic
      playbook.yaml           # authored: concrete API recipes per FE-APP-SHELL / state / forms (agent at authoring)
  code/fe/index.yaml      # FE-RULE-OWNERSHIP, rewritten: universal canon / Common-API lint / family lint
packages/
  grammar/src/
    families.ts               # the one family registry (generators, buttonIntent, lint factory)
    common/{spacing,state,intent,arrangement}.ts   # single copies
    <family>/dna.ts           # values only (gate reads via generated vocabulary)
  eslint/
    grammar-common/           # Common-API rules; lib/*.generated.mjs vocabulary from grammar (gate)
    grammar-<family>/         # thin factory + family-only rules (gate)
    fe/                       # universal canon incl. the moved universal rules (gate)
generated (untracked):
  rule index (rule -> knowledge id -> finding code)   # agent reads at authoring; gate cross-check
  per-law docs, DNA snapshot, package runtime/ copies
```

Who reads what: an authoring agent reads `contexts/ui` + the selected family's `family/idioms/playbook` + the generated rule index;
the gate runs the eslint packages (and canon-fe), which read only code-generated vocabulary; generators (`grammar-knowledge`,
rule-catalog, vocabulary, docs) read `packages/grammar` and knowledge rule ids and write only untracked or clearly generated files.
