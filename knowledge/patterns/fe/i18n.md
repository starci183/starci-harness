# Internationalization and formatting

Where readable text lives and how it reaches the screen. One pattern in every app, including a single-language app.

## FE-I18N Copy and formatting go through next-intl

Copy reaches the screen through `useTranslations` (or `getTranslations` in a server file); numbers, fixed dates,
relative values and currency through its formatter in the active locale. The catalogs are
`modules/i18n/messages/<locale>.json`.

Why: one library gives one catalog, one plural syntax and one formatter per locale.

Enforced by: R58 FE_I18N_LITERAL, R244.

## FE-I18N-1 One placement

Every app uses the `app/[locale]/` segment with `localePrefix: "as-needed"` and the product's declared default
locale. `modules/i18n` owns `routing.ts` (`defineRouting`), `request.ts` (`getRequestConfig`, reading the locale
from `next/root-params`) and the catalogs, and its public entry exposes routing and catalog data only;
`modules/routes` creates the locale-aware navigation (`createNavigation`) and the href builders. `proxy.ts` imports
the routing-only entry, never the navigation barrel. Several apps share the stack through an i18n package's explicit
exports.

Why: the proxy and rendered navigation run under different React export conditions; separate entries keep the request
interceptor from loading navigation's runtime, while one routing config feeds both.

Enforced by: R59 FE_I18N_PLACEMENT.

## FE-I18N-2 No display text in source

No tier writes display text: JSX text, `aria-label`, `title`, `placeholder`, `alt`, copy objects, validation and
toast messages, in any language. Text comes from the catalog or from labels the connected half resolved. There is no
escape annotation.

Why: a single escape turns the rule into a convention; with none, every string is translatable and checkable.

Enforced by: R58, R286.

## FE-I18N-3 Catalogs share one key set

Every locale has exactly the same keys; a key the source reads exists everywhere and a key nothing reads is deleted.
A new string adds its key to every locale in the same change.

Why: a missing key shows in production as raw key text.

Enforced by: R60 FE_I18N_CATALOG, R106 FE_I18N_KEYS.

## FE-I18N-4 Locale-aware navigation and metadata

Links and redirects use the locale-aware `Link`, `redirect` and `useRouter` of `modules/routes` with hrefs from its
builders; `generateMetadata` reads title and description from the catalog; switching locale navigates to the same path.

Why: a hand-built href drops the locale prefix.

Enforced by: R57, R59.

## FE-I18N-5 Each kind of value has one formatting owner

| Value | Arithmetic and parsing | Display |
|---|---|---|
| date and time | the one dayjs instance of `modules/dayjs` | the next-intl formatter |
| live relative time, countdown | none in the app | the grammar's time component with an ISO instant and the locale; it owns the shared clock |
| money, decimals | decimal.js in `modules/utils`, never float math | the next-intl formatter with the currency |

No component or hook owns a display clock, and `toLocaleString` is not used for display.

Why: math and display each have one owner, and live time has one ticker across the page.

Enforced by: R65.
