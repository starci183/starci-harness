- Fixed (h-deploy-age, `templates/app/ci-workflows/github/workflows/stack-deploy.yml`, `sync/stack-images.mts`): the deploy and rollback jobs of `stack-deploy.yml`, and the sealed image jobs of `images.yml`, install `age` and `age-keygen` right after "install SOPS" (`installAgeSteps`). The step downloads the age v1.2.1 linux-amd64 tarball, checks its sha256 before extracting and puts the two binaries on PATH: no apt install, no streamed installer. Run `starci app sync` to rewrite the app's managed workflows.
- Changed (h-cache-warm, check cache fingerprint, `cache/fingerprint.mts`): `knowledge/hfs/canon-pins.yaml` is a part of its own (`hfs:canon-pins`, `pkg:@starci/hfs:canon-pins`) that no family reads, and the `hfs` and `pkg:@starci/hfs` parts hold the digest of the rest of the package (`starciSourceParts` of the packed manifest). A release that only moves the pins no longer makes the hfs, secrets, wiring and db records cold; the pin rules run every run on the new pins. A build packed without the parts is keyed by its whole digest as before.

## 6.17.13 - 2026-11-25

- Changed (h-coverage-tiers): the coverage bar of R273 (floor, tiers, business bar) and HFS_NIVOOS_SPEC_MISSING are test and coverage obligations: an app that declares its `test` or `coverage` gate off (PROJECT-LINT-4) is not judged for them, and `coverage verify` prints `coverage: <gate>: off (declared: <reason>)` (`coverageObligationsOff`, `scripts/hfs/coverage-tiers.mts`).
- Changed (h-coverage-tiers, owner 2026-11-25): a business package (hfs.json `sides.nivoos`) is measured by the unit run but its barrels and type modules, at the business bar of 60 as a whole (the `tier-business` component of codecov.yml, R273) and the per-file floor; it stays out of the Sonar sources and `build:modules`. Added `HFS_NIVOOS_SPEC_MISSING` (R436): every `<name>.cell.ts` and `<name>.workflow.ts` of a declared package has `<name>.cell.spec.ts` / `<name>.flow.spec.ts` (or `.workflow.spec.ts`) beside it. The lint check cache replays a recorded finding at the level its rule has in the canon installed now (the canon's `levels`, else `recommended`), so a cached warning is never an error; the Sonar import (`reports/lint.sonar.json`) carries linter errors only, so a warning never counts in the gate's zero.
- Changed (h-coverage-tiers, owner 2026-11-25, BE-TEST-13, R273): coverage is held to tiers instead of 100 per measured file. `knowledge/sonar-gate.yaml` states every number once (`coverageBar`): tier A 85/80 lines/branches, B 75/65, C 60, a business package 60, the patch 80 (Sonar new code), every measured file 50, and the project a ratchet. Which module is in which tier is the app's declaration, hfs.json `sides.be.coverageTiers` (`{"A": ["domain/billing", "platform/outbox"], "C": ["integrations/*"]}`; an undeclared module is in tier B; `scripts/hfs/coverage-tiers.mts`). `starci app sync` renders the per-file floor into `be/jest.config.js` (`coverage.perFile`) and into `codecov.yml` the project ratchet (`target: auto`), the patch bar and one `tier-<letter>` component per tier at its bar; R273 judges the floor per file and every tier over the lcov. `services.codecov.target` is gone. The loosening check reads a coverage number by its key path (`gateLimits.floors` of design-truths.yaml: `tiers.A.lines` 85, ...) and a codecov or jest number below the per-file floor; `target: auto` is accepted on the project status only. Apps pick it up with `starci app sync`.
- Fixed (h-gitattributes-binary, the managed `.gitattributes` of `templates/app/skeleton`): `.starcistacks/** text eol=lf` no longer rewrites a binary file there (a brand reference PNG was corrupted in git); png, jpg, jpeg, gif, webp, avif, ico, woff, woff2, ttf, otf, pdf, zip, gz, tgz, mp4 and webm are `binary` after that rule. Apps pick it up with `starci app sync`.

## 6.17.12 - 2026-11-25

- Added (h-cli-bundle, R397 BE_CLI_CLIENT, `runtime/scripts/hfs/rules/cli.mts`): a client cli may declare `"bundle": true` in hfs.json and ship one self-contained file, so its users install it with no dependency tree: `be/apps/<app>/bundle.mjs` bundles the tsc output of its main into `dist/bundle/<bin>.cjs`, the bin points there, `files` holds `dist/bundle`, `prepack` is `node bundle.mjs` and the manifest lists no runtime dependency. Without the declaration the bin stays `dist/apps/<app>/src/main.js` and a tracked `bundle.mjs` is refused.
- The canon pins name @starci/grammar 0.59.1 and @starci/gallery 0.1.25.
- Added (h-grammar-ext-css, slot `app.gallery-look`, since 6.17.12): `gallery/look.json`, an app's optional declaration of each environment's web and api origin and the seed owner `starci app look` signs in as (the password a custody reference, never a value).
- Changed (h-schedule-cli-client, R268 HFS_SCHEDULE_UNDECLARED): an app of kind `client-cli` runs on the member's machine, so its own timers are its process schedule and R268 does not judge them.
- Added (h-work-prompts, slot `app.starciwork`, `runtime/scripts/hfs/path-findings.mts`): `.starciwork/prompts/**/*.md` holds an app's own authoring prompts, the Markdown its agents read when they write its content and only when a brief names them; HFS_ROOT_ENTRY_FORBIDDEN and HFS_SLOT_UNDECLARED no longer push such a folder out of the app, and the Work readers still leave it out, so the harness never loads it. Anything but Markdown there stays HFS_STARCIWORK_LITE_FORBIDDEN.
- Fixed (t195-grammar-ext, R93 machine `grammar`, `runtime/scripts/hfs/architecture/frontend-grammar.mts`; found by `app check --env prod --level full` on Grammar 0.55): the installed Grammar's optional peers (`optional: true` in `peerDependenciesMeta`: the core ext's `@xyflow/react`, `elkjs`, `d3-force`, `recharts`, `shiki`, ...) no longer count against the selected peers, so Grammar 0.55 no longer reports ARCH_GRAMMAR_CONTRACT_INVALID for every app; the required peers must still equal the selected peers exactly. A style source may import a core-ext stylesheet (`<package>/core/ext/<name>.css`, e.g. `core/ext/graph.css`, `core/ext/markdown.css`) that the installed Grammar declares in `exports`, beside the selected style entry, which must still be imported; any other Grammar CSS path stays ARCH_GRAMMAR_EXPORT_BYPASS. Product source (and so the eslint `grammar-entry` rule, which reports the machine's findings) may import a core-ext code entry (`<package>/core/ext/<name>` or one declared sub-entry, e.g. `core/ext/graph`, `core/ext/markdown/react`) that the installed Grammar exports to a target inside the package; a non-exported ext, a deeper path, an ext stylesheet in TSX, another family's entry and internal files stay refused.
