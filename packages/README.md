# packages

The packages StarCi apps install from npm: the quality canon, the Grammar and its lint families, the app implementation behind `starci app`, the shared front-end and back-end libraries, and the AI pool router. Each folder is its own npm package: install and test it inside its folder (`npm ci`, then `npm test`). A spec may read a sibling package's fixtures or source by relative path (`../eslint-canon-be/fixtures/...`, `../eslint-canon-fe/index.mjs`, `../grammar/src`), and a package whose published dependency is a sibling of this folder installs that sibling as a `file:../<name>` dev dependency under `install-links=true` (its `.npmrc`), so npm copies it instead of linking it; install every package before testing any.

A package's `runtime/` is committed source, edited in place. `eslint-canon-fe`, `eslint-canon-be`, `eslint-grammar-core`, `eslint-grammar-offset-pop` and `hfs` each bundle copies of the same runtime files (the canon pins, the Grammar catalog, the slot manifest and the architecture machine); a change to one copy is made to every copy in the same commit, and the pins name each `@starci` package by its folder here (`source: packages/<name>/package.json`) at that folder's version.

- `eslint-canon-fe` (`@starci/eslint-canon-fe`): the universal front-end ESLint canon (`starciFeConfig`, `loadHfs`) for TypeScript and Next.js; consumed by the `fe/eslint.config.mjs` of every StarCi app, beside its Grammar family config.
- `eslint-canon-be` (`@starci/eslint-canon-be`): the back-end ESLint canon (`starciBeConfig`, `loadHfs`) for Nest; consumed by the `be/eslint.config.mjs` of every StarCi app.
- `grammar` (`@starci/grammar`): the Grammar an app's UI is drawn in: the Common contract and the two families `core` and `offset-pop`, each with its root and stylesheet; consumed by every StarCi front end.
- `eslint-grammar-core` (`@starci/eslint-grammar-core`): the `core` family's lint factory (`coreGrammarConfig`) over the Grammar component API; versioned with `grammar`, with `@starci/eslint-canon-fe` as its peer.
- `eslint-grammar-offset-pop` (`@starci/eslint-grammar-offset-pop`): the `offset-pop` family's lint factory (`offsetPopGrammarConfig`), inheriting the core checks; versioned with `grammar`, with `@starci/eslint-grammar-core` as its peer.
- `stylelint-canon` (`@starci/stylelint-canon`): the CSS canon (Grammar tokens only, brand values only in `brand.css`); consumed by the `stylelint.config.mjs` of StarCi front ends.
- `heroicons` (`@starci/heroicons`): the glyphs `@heroicons/react` lacks, drawn in its style; imported by StarCi front ends.
- `event-stream` (`@starci/event-stream`): the server-sent-events client (Bearer renewal, Last-Event-ID resume, backoff, heartbeat, an SWR adapter); one instance per front end.
- `hfs` (`@starci/hfs`): the implementation behind `starci app` (scaffold, sync, check, lint, stack, db, codemod) for one product repository.
- `tsconfig` (`@starci/tsconfig`): the strict TypeScript presets `base`, `be`, `build`, `next` and `e2e`; extended by the tsconfig files of every StarCi app's back end and front end.
- `prettier-config` (`@starci/prettier-config`): the one Prettier config; consumed by every StarCi app's `prettier` setting.
- `jest-preset` (`@starci/jest-preset`): the jest config of a Nest repository and the shared unit-test double kit; consumed by the jest config and unit specs of StarCi back ends.
- `test-world` (`@starci/test-world`): the shared e2e world of every StarCi back end; pairs exactly with `@starci/jest-preset`.
- `ai-router` (`@starci/ai-router`): a NestJS module (`AiRouterModule.register` / `registerAsync`, the injectable `AiRouterService`) that routes OpenAI-compatible `chat`, `stream` and `embeddings` calls across many keys, models and providers, with breakers, rate-limit awareness, failover and redacted telemetry, and `@starci/ai-router/testing` (the fake provider and `AiRouterTestingModule`) for consumers' tests; its `npm test` also typechecks and lints, and fails under 90% line coverage.
