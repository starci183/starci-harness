# Changelog

## 0.3.0 - 2026-11-17

- Changed (`starci/data-entries@1`): every protocol line `serveStore` writes starts with `ANSWER_MARK` (`starci/data-entries@1 `), and `commandStore` reads the marked lines of a door's stdout, leaving out whatever the app framework logs before or after them (a NestJS CLI that logs at shutdown after the answer). A door that marks no line (built on 0.2.0 or earlier) is read by its JSON object lines, any other line being a log line; before, the answer had to be the last stdout line. New exports `ANSWER_MARK`, `protocolText`.

## 0.2.0 - 2026-11-17

- Added (`@starci/seed/git`): the adapter of a seed-standard that keeps its authored material in `raw/` (PROJECT-STACKS-13, R434). `renderStandard(content, outDir)` writes `{format, project, entries}` through `createGitDriver` into a scratch working copy (plaintext, purpose seed-standard) and replaces `manifest.json`, `data/`, `blobs/` and `index/` of `outDir`, leaving every other file; `takenAt` is `STANDARD_TAKEN_AT` (1970-01-01T00:00:00.000Z) and `source.environment` is `STANDARD_ENVIRONMENT` (standard), so the same content renders the same bytes in any entry order; a format that is no `<name>-seed-standard@<major>` is refused `DATA_FORM_REFUSED`. `runStandardAdapter(convert, argv)` is the body of an adapter's `main.ts`: `--raw` (default raw) and `--out` (default the repository root), exit 0, usage 2, a failed convert or render 1 with its code or error on one line. Types `StandardContent`, `StandardConvert`, `RenderOptions`, `AdapterIo`; constants `STANDARD_OUTPUTS`, `STANDARD_RAW`.

## 0.1.0 - 2026-11-14

The ports of the data standard (PROJECT-STACKS-13, PROJECT-STACKS-14) in one package: what must be kept, where a copy is kept, and one export written to several copies. It was first written under `@starci/common/data` and moves here before any release, so `@starci/common` stays at 1.0.1.

- `exportOnce` names a failing store and its cause in the refusal: `DATA_STORE_FAILED` params `{store, cause}`, the cause read by shape (a coded error of any `@starci/common` copy by its code, a driver error by its class, SQLSTATE and table), never by message; `causeLabel` is exported; an empty store is a valid export.
- Added: `@starci/seed`: the closed vocabulary (`StoreKind` database | storage, `DriverKind` git | s3, `DataPurpose` seed-standard | seed-backup, `StoreLevel`, `EntryForm`, the git copy cap `GIT_CAP_BYTES` 500 MiB (the whole snapshot, history not counted) with `GIT_WARN_BYTES` 400 MiB and `GIT_SHARD_BYTES` 4 MiB); `DataEntry`, `DataManifest` (`starci/data-manifest@1`), `ManifestBuilder`, `canonicalJson`, `recordEntry`, `blobEntry`, `setDigest`, `exportDigestOf`, `manifestProblems`; the `StoreAdapter` and `DriverAdapter` ports with `ImportReport`, `Holding`, `CopyRef`, `CopyReceipt`, `CopyVerdict` and the coded `DataRefusal` (retry class configuration | transient), a `DomainError` of `@starci/common`; `StoreAdapter.import` is an upsert by natural key that keeps each row's identity (`identityOf`; never delete-and-recreate; a key not named is left alone); the copy contract `exportOnce`, `unchangedSince`, `writeEverywhere` (each driver an isolated leg, outcome complete | partial | failed), `compareCopies`, `chooseCopy`, `restoreFrom`; the line protocol `starci/data-entries@1` (`serveStore` for an app's store command, `commandStore` for the harness side).
- Added: `@starci/seed/git`: `createGitDriver`, the `git` driver over a local working copy (cloned, pulled and pushed when a remote is given): `manifest.json` + record shards `data/<store>/<set>/<shard>.json` (hash-prefix shards, the width only grows) + blob chunks `blobs/<store>/<set>/<aa>/<id>[.<n>].bin` + `index/`; files at most 4 MiB; sealing follows the purpose (a `seed-standard` is plaintext, a `seed-backup` is sealed with sops in binary mode to its environment's age recipients, `*.sops.json`); a file whose plaintext did not change is never rewritten and an unchanged export commits nothing; a snapshot past the cap is refused `DATA_GIT_CAP_EXCEEDED` (configuration: needs s3), past 400 MiB warned `DATA_GIT_CAP_NEAR`; `verify` checks manifest, sealing policy, stray, missing and unsealed files, envelopes, the cap and, with an identity (or for a plaintext copy), every digest; `.gitattributes` `* -text` keeps line endings from touching a file.
- Added: `pinRepository` (a copy repository at one pinned commit: bare mirror in a cache, `readText`, `openSealed` in memory with an identity) and `openReviewTree` (writes and sops sealing into a working tree a person reviews), for a kind a project defines on top of the standard.
- Added: `@starci/seed/postgres`: `postgresStore({id, run, schemas?, exclude?, pageRows?})`, the `database` store (level `physical`, purpose `seed-backup`) that copies the whole relational database behind `StoreAdapter` as a per-table row export through SQL this package owns (not a pg_dump archive: its bytes change on every run and it is one blob; not the app's entity layer: it covers only modelled entities under the app role). One set per ordinary or partitioned-parent table `<schema>.<table>`, rows keyed by primary key, every column read as text in a REPEATABLE READ snapshot under fixed session settings so an unchanged database exports the same bytes (the git driver commits nothing); entries come in byte order from SQL (`ORDER BY convert_to(key, 'UTF8')`, keyset pages). Import is one READ COMMITTED transaction with `session_replication_role = replica` (owner role), an upsert by primary key with exact created/updated/unchanged counts, `mirror` deletes, sequences set to the column maximum, a dry run that rolls back. Excluded and keyless tables are listed in `describe().cannot` with reasons; a SQL failure is `DATA_STORE_FAILED` with the SQLSTATE only. The app hands a `PostgresRunner` (`query`, `transaction`) and no SQL. `storeContract` takes an optional `{change}` for a store whose rows are typed.
- Added: `@starci/seed/testing`: `memoryStore`, `memoryDriver` (with failure and corruption switches), `memorySpool`, and the contract suites `storeContract` and `driverContract` every real adapter runs against its fakes.
