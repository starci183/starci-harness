# Changelog

## 0.1.0 - 2026-11-14

The ports of the data standard (PROJECT-STACKS-13, PROJECT-STACKS-14) in one package: what must be kept, where a copy is kept, and one export written to several copies. It was first written under `@starci/common/data` and moves here before any release, so `@starci/common` stays at 1.0.1.

- Added: `@starci/seed`: the closed vocabulary (`StoreKind` database | storage, `DriverKind` git | s3, `DataPurpose` seed-standard | seed-backup, `StoreLevel`, `EntryForm`, the git copy cap `GIT_CAP_BYTES` 500 MiB (the whole snapshot, history not counted) with `GIT_WARN_BYTES` 400 MiB and `GIT_SHARD_BYTES` 4 MiB); `DataEntry`, `DataManifest` (`starci/data-manifest@1`), `ManifestBuilder`, `canonicalJson`, `recordEntry`, `blobEntry`, `setDigest`, `exportDigestOf`, `manifestProblems`; the `StoreAdapter` and `DriverAdapter` ports with `ImportReport`, `Holding`, `CopyRef`, `CopyReceipt`, `CopyVerdict` and the coded `DataRefusal` (retry class configuration | transient), a `DomainError` of `@starci/common`; `StoreAdapter.import` is an upsert by natural key that keeps each row's identity (`identityOf`; never delete-and-recreate; a key not named is left alone); the copy contract `exportOnce`, `unchangedSince`, `writeEverywhere` (each driver an isolated leg, outcome complete | partial | failed), `compareCopies`, `chooseCopy`, `restoreFrom`; the line protocol `starci/data-entries@1` (`serveStore` for an app's store command, `commandStore` for the harness side).
- Added: `@starci/seed/git`: `createGitDriver`, the `git` driver over a local working copy (cloned, pulled and pushed when a remote is given): `manifest.json` + record shards `data/<store>/<set>/<shard>.json` (hash-prefix shards, the width only grows) + blob chunks `blobs/<store>/<set>/<aa>/<id>[.<n>].bin` + `index/`; files at most 4 MiB; sealing follows the purpose (a `seed-standard` is plaintext, a `seed-backup` is sealed with sops in binary mode to its environment's age recipients, `*.sops.json`); a file whose plaintext did not change is never rewritten and an unchanged export commits nothing; a snapshot past the cap is refused `DATA_GIT_CAP_EXCEEDED` (configuration: needs s3), past 400 MiB warned `DATA_GIT_CAP_NEAR`; `verify` checks manifest, sealing policy, stray, missing and unsealed files, envelopes, the cap and, with an identity (or for a plaintext copy), every digest; `.gitattributes` `* -text` keeps line endings from touching a file.
- Added: `pinRepository` (a copy repository at one pinned commit: bare mirror in a cache, `readText`, `openSealed` in memory with an identity) and `openReviewTree` (writes and sops sealing into a working tree a person reviews), for a kind a project defines on top of the standard.
- Added: `@starci/seed/testing`: `memoryStore`, `memoryDriver` (with failure and corruption switches), `memorySpool`, and the contract suites `storeContract` and `driverContract` every real adapter runs against its fakes.
