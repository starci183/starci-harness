# Internationalization and formatting

Where readable text lives, how the locale is chosen and how a value is formatted. One pattern in every app,
including a single-language app.

## FE-I18N-1 next-intl is written once: routing, request config, navigation

Every app routes under `app/[locale]/`; the next-intl stack (`defineRouting` with the locales, default locale, prefix
mode and locale cookie; `createNavigation`; the request config; the proxy's locale negotiation; the layout's locale
read) is written once, in the shared i18n package when two apps exist (its subpath exports keep `./proxy` free of the
navigation runtime) or in the app's `modules/i18n`; each app's `modules/i18n/request.ts` only names its catalogs.

Why: the proxy and rendered navigation run under different React export conditions, and one routing table read by
both keeps the locale the same on every path.

```ts
// modules/i18n/request.ts
import { createRequestConfig } from "@<project>/i18n/request"

export default createRequestConfig("web", async (locale) => (await import(`./messages/${locale}.json`)).default)
```

Enforced by: R59 (`i18n-stack-in-one-module`, `locale-segment-is-locale`, `no-second-i18n-stack`; hfs `i18n-placement`),
R58 (`html-lang-from-locale`).

## FE-I18N-2 No display text in source

No tier writes text a reader sees or hears (JSX text, `aria-*`, `label`, `title`, `alt`, `placeholder`, copy objects,
validation and toast messages, in any language): a connected half or a page owner reads it from the catalog with
`t()` and passes it down resolved; there is no escape comment.

Why: a single escape turns the rule into a convention; with none, every string is translatable and checkable.

Enforced by: R58 (`no-hardcoded-copy`, `no-copy-resolution-below-block`), R286 (`no-copy-in-call`).

## FE-I18N-3 Every locale has the same keys, and every key is read

`modules/i18n/messages/<locale>.json` holds one top-level namespace per feature; every locale has exactly the same
keys, a key the source reads exists everywhere, a key nothing reads is deleted, and a key built at run time or read
through a handed-in translator is declared with its reason in `fe/i18n-dynamic-keys.yaml`.

Why: a missing key shows in production as raw key text, and an unread key is copy nobody maintains.

Enforced by: R60 (hfs `i18n-catalog`), R106 (`i18n-keys`), R280 (hfs `unused-symbol`).

## FE-I18N-4 Navigation is locale-aware and every path comes from `modules/routes`

Links, redirects, `useRouter` and `usePathname` come from the locale-aware `navigation` of the i18n entry; every path
is built in `modules/routes` (`<AREA>_ROUTES` objects `as const` and `<x>Path(...)`/`<x>Href(...)` builders); the
proxy, which cannot load that barrel, is the one place a path is spelled again, with a comment saying so.

Why: a Next `Link` or a hand-built path drops the locale and points at a 404 when the route moves.

```ts
/** The routes of the signed-out flow; every link to them is built here. */
export const AUTH_ROUTES = { login: "/login", signup: "/signup", reset: "/reset-password" } as const

/** The sign-in path that returns the viewer to `next` after signing in. */
export const loginPath = (next?: string): string =>
    next === undefined ? AUTH_ROUTES.login : `${AUTH_ROUTES.login}?next=${encodeURIComponent(next)}`
```

Enforced by: R59 (`navigation-from-intl`, `no-native-anchor`), R57 (`no-hardcoded-route`, `owner-reachable`).

## FE-I18N-5 Each kind of value has one formatting owner

| Value | Arithmetic and parsing | Display |
|---|---|---|
| date and time | the one dayjs instance of `modules/dayjs`, in the product time zone of the i18n entry | `useFormatter` / `getFormatter` |
| live relative time, countdown | none in the app | the grammar's time component with an ISO instant; it owns the shared clock |
| money, decimals | decimal.js in `modules/utils`, never float math | the next-intl formatter with the currency |

No unit owns a display clock, and no value is shown through `toLocaleString`, `Intl.*` or `toFixed`.

Why: arithmetic and display each have one owner, and live time has one ticker across the page.

Enforced by: R59 (`use-intl-formatter`), R65 (`no-app-relative-clock`).
